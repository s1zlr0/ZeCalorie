# Внутренний список внесённых ошибок (НЕ выкладывать в публичный репозиторий / не показывать команде-тестировщику)

Пересмотрено: все ошибки теперь воспроизводятся обычными действиями в интерфейсе за 1–2 минуты, без доступа к коду, без изменения системных часов и без точного тайминга кликов.

| № | Тип ошибки | Суть | Как найти (шаги для тестировщика) |
|---|-----------|------|-------------------------------------|
| 1 | Логическая (расчёт) | В формуле Миффлина-Сан Жеора перепутаны местами коэффициенты для мужского и женского пола (`+5`/`-161`) | Ввести одни и те же вес/рост/возраст сначала с полом "Мужской", затем "Женский", сравнить результат с формулой из ТЗ/открытым калькулятором нормы — результаты будут отличаться от ожидаемых и как будто "поменяны местами" между полами |
| 2 | Логическая (отображение) | После удаления записи итоговая сумма калорий и "осталось" в сводке не обновляются — список меняется, а числа под ним остаются старыми | Добавить 2–3 приёма пищи, посмотреть сводку внизу, удалить один — сводка не изменится, пока не добавить новую запись |
| 3 | Интерфейсная | Кнопка «Добавить» активна всегда, даже с пустым полем «Название» и/или «Калории» | Нажать «Добавить», не заполнив поля — создастся пустая запись с 0 ккал вместо предупреждения об ошибке |
| 4 | Валидация | Поле «Калории» принимает отрицательные числа без проверки | Ввести "-500" в калории и добавить — запись добавится, итоговая сумма за день уменьшится |
| 5 | Необработанное исключение (краш) | Нет проверки на нечисловой ввод в полях "Калории", "Вес", "Рост", "Возраст" | Ввести буквы вместо числа в любое из этих полей и нажать соответствующую кнопку — приложение упадёт с ошибкой |
| 6 | Локализация | Дробное число с запятой (например "70,5") не распознаётся как число | Ввести дробное значение через запятую в любое числовое поле — приведёт к тому же краху, что и баг №5, вместо корректной обработки |
| 7 | Интерфейсная (косметика) | Длинные названия блюд обрезаются по ширине списка без переноса строки или многоточия | Добавить приём пищи с названием на 50+ символов и посмотреть, как оно отображается в списке |
| 8 | Логическая (согласованность данных) | Если удалить все записи за день, дата всё равно остаётся в списке вкладки «История» — при выборе показывается пустой день | Добавить 1 запись сегодня, удалить её, перейти на вкладку «История» — дата за сегодня всё ещё в списке, хотя записей нет |

## Почему это лучше предыдущей версии

- Убраны баги, которые требовали смены системной даты (полночный переход) или точного тайминга кликов (гонка при удалении) — их нереально найти в рамках обычной сессии тестирования.
- Все 8 ошибок находятся через стандартный ввод/вывод: пустые поля, отрицательные числа, нечисловой ввод, длинный текст, последовательность добавить→удалить→проверить.
- Сохранено разнообразие типов: логические (расчёт, отображение, согласованность данных), интерфейсные, валидационные, крэш, локализация — как требует задание («различной природы»).

## Рекомендации по оформлению в отчёте

Для каждой ошибки укажите: тип, шаги воспроизведения, ожидаемый и фактический результат — по аналогии с примером TC-001 из методички.
